# Лабораторная работа № 6. Проектирование REST API

**Наименование работы:** REST API, документация OpenAPI и конвейер непрерывной интеграции.

**Вариант задания:** прием абитуриентов в учреждение образования. Сущность сервиса — заявление (вход I1, узел A1 модели IDEF0).

**Автор:** Кравченко А.С.

## Запуск

Из корня репозитория:

```powershell
docker compose up -d --build
```

Сервис слушает порт 8000. Интерактивная документация Swagger UI: http://localhost:8000/docs.

Остановка:

```powershell
docker compose down
```

Данные хранятся в памяти процесса и исчезают при перезапуске контейнера.

## Методы

| Метод | Путь | Успех | Ошибка |
| --- | --- | --- | --- |
| GET | /api/v1/applications | 200, список заявлений | — |
| GET | /api/v1/applications/{id} | 200, одно заявление | 404, если идентификатора нет |
| POST | /api/v1/applications | 201, созданное заявление | 400, если поля не прошли проверку |
| DELETE | /api/v1/applications/{id} | 200, удаленное заявление | 404, если идентификатора нет |

Поля заявления: фамилия, имя и отчество (до 150 знаков), специальность (до 150 знаков), форма обучения (`очная` или `заочная`), контакт (до 100 знаков).

Пример создания:

```powershell
curl -X POST http://localhost:8000/api/v1/applications -H "Content-Type: application/json" -d "{\"full_name\":\"Сидоров Петр Алексеевич\",\"specialty\":\"Автоматика и телемеханика на транспорте\",\"study_form\":\"очная\",\"contact\":\"sidorov@example.com\"}"
```

## Сборка в GitHub Actions

Файл `.github/workflows/ci.yml` запускается при push в `main` и при pull request в `main`. На `ubuntu-latest` выполняются checkout, установка Python 3.11, flake8 и `docker build`.

Ветка с работой — `lab_6`. Зеленый прогон появляется после pull request этой ветки в `main`.

## Вопросы для защиты

**PUT и PATCH.** PUT заменяет ресурс целиком: в теле должны быть все поля. PATCH меняет только переданные поля, остальные остаются. В этом сервисе этих методов нет: по заданию реализованы чтение, создание и удаление.

**OpenAPI.** Спецификация описывает пути, типы полей и коды ответов так, что их читает и человек, и программа. Swagger UI на `/docs` строится из этого описания, клиент можно сгенерировать без разбора исходного кода.

**Continuous Integration.** CI проверяет каждое изменение до слияния в общую ветку. GitHub Actions на pull request запускает линтер и сборку образа, поэтому ошибка видна в запросе на слияние, а не после него.

**Сборка на ubuntu-latest.** Образ собирается на чистой машине GitHub, а не на компьютере автора. Так проверяется, что Dockerfile воспроизводим и не зависит от локально установленных пакетов.
